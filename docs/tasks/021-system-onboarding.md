Four short wizard steps with a visible stepper, Back/Next, preserved entries when changing language/step, explicit validation and a final Save system action:

1. **Site and decision**: site name + kind (vessel/plant/data centre), system name, engineering question (hydraulic operation, mechanical condition, energy assessment). Explain what decision the chosen question supports in one sentence. Template: one pump + motor + control valve, explicitly a user-defined/conceptual loop, never inferred benchmark piping. A simple SVG illustrates component relationships; no equipment controls.
2. **Equipment passport**: editable pump and motor names, design flow m³/h, design head m, rated speed rpm and motor rating kW; valve name/type/placement (default after pump is an explicit template assumption), known/unknown is allowed rather than fake zeros. Validation: supplied numeric ratings positive and finite. Existing benchmark PUMP-04 metadata may prefill only via explicit **Use challenge example** action. Display provenance for prefilled values and keep new configuration distinct. No silent fake manufacturer/certification.
3. **Device, sensors and source**: device label, planned interface selection (file/local network/gateway). Physical gateway is a proposal; interface configuration is not a successful connection. Choose installed/available channels and point locations (Ps suction, Pd discharge, Q line, n shaft/drive, motor input power, housing vibration/temperature, valve position). Units visible, status installed vs proposed distinct. Offer purpose-specific suggested sensor sets (hydraulic/mechanical/energy) as proposals, not bulk installation that automatically upgrades readiness. Explain missing perspective and integration effort/verification for each set; prioritize existing signals or temporary measurement first.
   Data sources with honest provenance:
   - **Challenge recording**: explicit load of the existing reviewed PUMP-04 minute from diagnosis-comparison.json.rawMinute. Only t, ps, pd, q, n; historical synthetic source, date range visible; no extra power/vibration/valve telemetry implied by passport availability. Fetch only existing committed bundle; no vendor/test reads or bundle edits. P04 values are noisy; do not portray this as healthy reference.
   - **Local CSV import**: actual browser file selection and parsing, preview row count/time window/channels, no upload. Provide a downloadable CSV template and concise visible format guidance. Timestamp ISO8601 with timezone; headers encode documented units, e.g. timestamp_utc, suction_pressure_kpa, discharge_pressure_kpa, flow_m3_h, motor_speed_rpm, motor_power_kw, vibration_rms_mm_s, bearing_temp_c, valve_position_pct. Strict declared allowlist, reject unknown/duplicate headers, invalid/nonfinite numbers, impossible timestamp, duplicates/out-of-order rows, oversized files/row count with useful EN/RU messages. Allow absent channels and blank missing readings, show coverage, don't zero-fill. Bound ~2 MB/10000 rows and local storage footprint; handle storage quota/unavailable gracefully. Store compact bounded samples or summary for readiness, disclose if full file is not persisted. No misleading claim of full historian. Imported data must be isolated from benchmark diagnosis engine.
   - **Network/gateway (planned)**: selectable configuration with endpoint/transport metadata if useful but no credentials; status Not connected / Configuration only. No real requests, fake online indicator, play-live timers or automatic diagnosis. This slice proves offline file path; actual ingestion is future work. Optional authored connection simulation only if clearly marked and bounded, not necessary to finish the slice.
4. **Readiness and decision**: separate installed/configured measurements, actually received samples and analysis capabilities. Three compact capability cards for hydraulic/mechanical/energy with plain status and exact missing conditions, no opaque readiness percentage or health score. Use physics-aware prerequisites: ΔP needs simultaneous Ps/Pd at pump taps and comparable pressure reference; operating point additionally Q and relevant reference/curve; comparing regimes needs speed/context; energy assessment needs input power+flow+head and geometry/density assumptions; bearing fault inference requires waveform/bandwidth/reference, RMS alone is trend only; valve position alone does not prove flow. Do not label formal diagnosis ready from channel checkboxes or one noisy minute. Show a tiny actual preview chart (pressure-rise trend if simultaneous Ps/Pd rows exist) and time/source, otherwise explicit no measurements. Proposed channel cannot satisfy actual receipt. User-configured channels with conflicting import columns/locations must produce a mapping/verification warning rather than silently treating imported values as trustworthy installed sensors.
   **Next useful step**: based on selected question + actual inputs, explain what can be reviewed now and which independent verification or temporary measurement would reduce uncertainty. Optionally suggest permanent set only with purpose and open installation/cost questions. Include concise visible "hardware design / certification / installation not verified" in the appropriate proposal details, not repeated boilerplate. No unsupported savings or accuracy claim.
